## 一眼看懂

**原始提示词**

```text
根据我贴的财报，告诉我这家公司未来一年股价能涨多少。
必须给准确百分比和明确买卖建议，把完整思考过程写出来。
```

**Prompt Doctor 的处方**

```text
根据下方财报，对公司未来 12 个月的股价表现做情景分析。

1. 区分财报事实、基于事实的推断和依赖假设的预测。
2. 给出悲观、基准、乐观三种情景；每种列出估值区间、
   关键假设、触发信号和可能推翻判断的新证据。
3. 关键数据注明来源和基准日期；无法核实的信息标记“待核实”，不要猜测。
4. 给出简洁依据和关键计算步骤，不要求隐藏的完整思维过程。

输出：核心结论 → 财务事实 → 情景表 → 风险与反证 → 待核实信息。
```

变化不在于“写得更长”，而在于把虚假精度换成了**证据、假设、区间和反证条件**。

## 它会做什么

- **诊断关键缺口**：目标、输入、受众、交付物、约束、验收标准、时效与能力边界。
- **选择最小有效改法**：简单任务保持简单；复杂任务才拆阶段。
- **保留原意和语气**：只修指令，不擅自改成交付物，也不把口语变成官样文章。
- **处理高风险要求**：拒绝“100% 准确”“保证原创”“精确预测”等无法兑现的承诺。
- **支持复诊**：根据实际输出做补丁式修订，避免每次从头重写。

## 工作方式

```text
已有 prompt
    ↓
只找影响结果的缺口
    ↓
使用当前上下文补齐可得信息
    ↓
选择最小升级 / 分阶段 / 增量编辑 / 情景分析
    ↓
输出可直接复制的优化版
```

默认输出顺序为：**诊断 → 优化版 → 改动说明 → 待填写 → 能力边界**。用户只想拿结果时，也可以只返回优化后的代码块。

## 安装

将仓库克隆到 Codex 可发现的技能目录：

```bash
git clone https://github.com/cybercyrus-gh/prompt-doctor.git \
  ~/.agents/skills/prompt-doctor
```

更新已有安装：

```bash
git -C ~/.agents/skills/prompt-doctor pull --ff-only
```

## 使用

显式调用技能，并贴上要修的现有提示词：

```text
使用 $prompt-doctor 优化这个 prompt：

帮我写一篇小红书文案介绍咖啡店，要有网感，去 AI 味。
```

也可以用于复诊：

```text
使用 $prompt-doctor 复诊。下面是原 prompt、实际输出和我不满意的地方；
只修改相关指令，其余保持不变。
```

适合这些表达：

- “优化这个 prompt”
- “提示词怎么写更好？”
- “AI 输出不对味，帮我回头改指令”
- “只改提示词的这一部分，其他别动”

不用于从零代写完整提示词、直接润色交付物，或设计复杂的 Agent/system prompt 架构。

## 设计原则

1. **不过度工程化**：简单任务不会被膨胀成一页模板。
2. **不凭空添加规则**：精确数字、禁词和平台规范必须来自用户、材料或稳定要求。
3. **不索取完整思维链**：需要可审计性时，改要证据、假设、计算步骤和核查清单。
4. **不制造确定性**：预测类任务改成情景、区间、触发信号和反证。
5. **不自动沉淀用户内容**：只有用户明确要求时，才匿名化保存案例。
