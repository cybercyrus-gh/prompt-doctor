## 一眼看懂

**原始提示词**

```text
帮我分析一下 XXXX 下周股票走势。
```

**诊断**

这是判断 / 预测型任务。“分析走势”的任务边界不清，也缺少标的、基准日期、信息范围和验收标准。提示词可以把任务改成可核查的研究流程，但不能让 AI 可靠预知短期涨跌。

**Prompt Doctor 的处方**

```text
帮我分析一下 [公司名称 / 股票代码] 下周可能的走势。不要给“必涨 / 必跌”的单点预测，把结论写成条件化情景。

背景：
- 分析基准日期：[YYYY-MM-DD]
- 可用材料：[行情 / 公告 / 财报 / 行业信息；按实际填写]

分五步：
1. 信息汇总：整理截至基准日期可核实的价格与成交量、公司公告、行业动态和大盘环境。注明来源和日期；无法核实的内容标 `[待核实]`，不要猜。
2. 多空推演：分别给出 3 条最强的看多与看空逻辑，每条写清依据、证据强度、关键假设和证伪信号。
3. 交叉反驳：让多方逐条回应空方，空方再逐条回应多方，找出证据最弱的论点。
4. 关键假设：列出最影响下周判断的 3 个假设，并说明什么新信息会推翻它们。
5. 情景化：给出偏强 / 震荡 / 偏弱三种情景，各自包含触发条件、观察信号和失效条件；不要强行给精确概率或点位。

先完成第 1 步，输出后停下来等我确认，再继续后面的步骤。
```

**说明**：原意仍然是分析下周走势，但从模糊预测改成了可分步核查的判断过程。

**预警**：优化 prompt 也不能让 AI 准确预知下周股价；这份处方提供的是条件化情景，不是确定性预测。

## 它会做什么

- **9 项诊断**：角色、背景、任务、模式、受众、约束、示例、验收和负向约束。
- **任务分类**：区分成品型与思考型、单轮与多步，决定使用变体 A 还是变体 B。
- **先取材再提问**：优先使用当前会话和项目材料，只有用户才知道的信息才留空或提问。
- **保留原意和语气**：简单任务只补缺口，复杂判断任务才做结构化升级。
- **复诊与预警**：根据实际输出只补主要缺口；对 AI 本质做不好的任务直接换用法。

## 工作方式

```text
已有 prompt
    ↓
9 项检查表诊断缺口
    ↓
成品型 / 思考型 · 单轮 / 多步
    ↓
从当前上下文取材
    ↓
变体 A 最小升级 / 变体 B 结构化升级
```

默认输出顺序：**诊断 → 变体 → 说明 → 预警（如适用）**。

```bash

```

## 使用

直接用自然语言提出需求并贴上原始提示词，不必显式调用技能：

```text
优化这个 prompt：
[粘贴原始提示词]
```

```text
帮我改下提示词：
[粘贴原始提示词]
```

```text
这个 prompt 跑出来不对味：
原始 prompt：[粘贴]
实际输出：[粘贴]
我不满意的地方：[具体说明]
```

也可以显式使用 `$prompt-doctor`，但这不是必需的：

```text
使用 $prompt-doctor 优化下面的提示词：
[粘贴原始提示词]
```

这些说法都会触发对应流程：

- “优化这个 prompt”
- “帮我改下提示词”
- “提示词怎么写更好？”
- “AI 输出不对味，帮我回头改指令”
- “只改提示词的这一部分，其他别动”

不用于从零代写全新 prompt、直接优化代码或文案本身，以及 Agent system prompt 深度工程。

## 三条护栏

1. **不过度工程化**：简单任务不给 500 字模板。
2. **不加做不到的约束**：把“保证准确”等要求改成标注不确定处和待核实项。
3. **保留用户语气**：优化提示词，不擅自改变用户真正想做的事。

技能还定义了案例生长机制：遇到有代表性的新模式时先询问一次，用户明确同意后才匿名化追加；超过 10 条时先修剪同类案例。
